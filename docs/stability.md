# Codex Desk Buddy 稳定性验证

自动化稳定性验证使用固定种子 `0x5eedc0de`，因此每次运行可复现同一组数据和故障选择。执行：

```bash
npm run test:stability
```

## 当前直接证据

JavaScript 故障注入使用真实 `DeviceSession`、协议 v4、AES‑256‑GCM 和内存传输端点，不绕过认证或可靠消息层：

- 建立 501 个全新双向认证会话，交替使用 USB 与 Wi‑Fi，形成 500 次主链切换。
- 每个会话随机但可复现地注入一种故障：重复设备命令、丢失 Bridge 快照、旧事件与新快照乱序、命令 ACK 丢失。
- 每次连接都必须完成相同会话 ID 的双向认证、加密初始快照和 ACK 清空；命令重试不得重复执行业务操作。
- ACK、心跳和错误不占用可靠序号；丢失 ACK 后原命令以相同序号重试，接收端只重发 ACK，不执行第二次，也不触发伪序号缺口。
- 250 次 Pet 替换均先注入坏块和中断：坏块必须被 SHA‑256 拒绝，未完成提交必须保留旧 Pet，再按照精确缺失区间乱序续传并逐字节验证新 Pet。

原生 C++ 固件核心测试另外完成：

- 50,000 次双槽 active 指针写入，其中固定比例模拟写入中断；任意时刻必须保留一个有效旧槽。
- 10,000 次四块乱序资源传输；完整资源只成功一次，重叠范围始终拒绝。
- 50,000 次序号接收、重复消息和周期性快照跨缺口恢复。

一次成功运行会打印实际完成计数；任何认证、超时、幂等、哈希、指针或内容不变量失败都会立即以非零状态退出。该命令也重新编译并运行原生 C++ 测试，不依赖预先生成的二进制。

## 这份验证不能证明什么

内存传输可以精确模拟协议层丢包、重复与乱序，但不能替代真实 USB 驱动、2.4 GHz 射频、路由器、电脑睡眠、microSD 控制器或电源掉电波形。因此以下结果必须等设备到手：

- v0.2.0 固件写入后的 USB 插拔、BLE 长稳、Wi‑Fi 弱信号和路由器重启下的实际恢复时间。
- 摄像头连续多次初始化/释放、JPEG 峰值内存、语音录音与 TTS 互斥下的真实硬件稳定性。
- USB 加密配网的插拔恢复、Wi‑Fi 凭据写入与设备重启体验。
- 多品牌 microSD、写入中断和真实随机断电。
- 连续 72 小时运行、内存趋势、机身温度和充电状态。

自动化的结论是“非物理逻辑在指定规模内保持不变量”，不是“硬件已经通过量产长稳”。
